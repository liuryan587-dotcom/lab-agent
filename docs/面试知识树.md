## 一、怎么用这份文档

**核心原则：以项目为索引的理论清单。**

同样是学 HTTP 状态码：

- ❌ 按教材背：「301 永久重定向、302 临时重定向、304 协商缓存」
- ✅ 按项目背：「我的 `BusinessException` **故意返回 HTTP 200**，业务错误码放在 body 的 `code` 里。代价是前端拦截器必须同时判断两套逻辑；好处是前端统一走成功回调、不会被浏览器/网关当成错误拦截。换一种设计就是业务错误也返回 4xx，那样前端要处理两套 catch。」

第二种答法才拿得到分，因为它证明**你想过取舍**，而不只是看过文档。

**三条轨道并行：**

| 轨道 | 内容 | 组织方式 | 能否延后 |
| --- | --- | --- | --- |
| A 工程主线 | [学习路线.md](学习路线.md) 的 L1–L5 | 按项目模块推进 | 已在跑 |
| B 理论副线 | 本文件第三章 | 按面试知识树，**不按课程顺序** | 能延后但会打折 |
| C 算法手写 | 本文件第四章 | **每天 30 分钟，不许断** | ❌ 绝对不能延后 |

> **为什么理论上要"分开组织、同步推进"**：完全合并 → 只会用不会讲边界；完全分开 → 面试时无法在 30 秒内从项目跳到原理，而面试的常态就是**从项目切入问原理**。

### P0-0 · 项目本身（对你权重最高）

**必答问题**

1. 一句话介绍项目解决了什么问题
2. 画架构图，讲清一次请求的完整链路
3. 为什么这么分层？Service 层解决什么问题？
4. 遇到过最难的问题是什么，怎么定位的？（**必须有真实故事，不能编**）
5. 如果用户量涨 100 倍，哪里先崩？
6. 你觉得这个项目哪里做得不好？（**这题考的是自我认知，几乎没有候选人准备好**）

**用你项目的点来讲**

- 链路：`Login.vue` → `api/auth.js` → `request.js` 拦截器 → `/api/auth/login` → `LoginRequest` 校验 → `auth_service.login` → `db.query(User)` → bcrypt 校验 → 签发 JWT → 统一 `Response` → 拦截器判断 `body.code` → 存 token → 路由跳转
- 分层的价值：`api` 只收参返回、`services` 放业务规则、`models` 描述表、`schemas` 约束进出数据形状。反例：如果把 bcrypt 校验和 JWT 签发写进路由函数，那么"管理员重置密码"这个新接口就得复制一遍逻辑
- 薄弱点（诚实答，反而加分）：`create_all` 不是迁移方案；没有测试；业务错误返回 200 增加了前端判断成本；路由守卫只判断 token 是否存在、**不判断角色**

### P0-1 · Python 语言基础

**必答问题**

- 可变对象 vs 不可变对象；`a = [1]` / `b = a` / `b.append(2)` 之后 `a` 是什么
- 深拷贝 vs 浅拷贝
- `is` vs `==`；为什么 `a = 256; b = 256; a is b` 是 `True` 而 `1000` 是 `False`
- 闭包是什么，有什么坑（循环变量捕获）
- 装饰器原理（`@` 语法糖展开成什么）
- 生成器 / 迭代器 / `yield`；为什么生成器省内存
- `with` 上下文管理器原理（`__enter__` / `__exit__`）
- `*args` 与 `**kwargs`；`*` 在函数签名里的强制关键字参数用法
- **GIL 是什么，为什么 Python 多线程不能并行跑 CPU 密集任务，那 `asyncio` 为什么能提高 IO 吞吐**
- `list` / `tuple` / `dict` / `set` 的底层与查找复杂度

**用你项目的点来讲**

- `get_db()` 里的 `yield` 就是生成器：FastAPI 依赖注入靠它实现"请求结束自动 `close`"（[database.py](../backend/app/database.py)）
- `MAX_FILE_SIZE` / `ALLOWED_EXTENSIONS` 是模块级常量，讲"可变默认参数陷阱"时可以用 `PageResponse` 的 `list: Any = []` 对比说明——Pydantic 会深拷贝默认值，所以这里安全，但普通 Python 函数里写 `def f(x=[])` 就是 bug
- 为什么你的路由都写 `def` 而不是 `async def`：**FastAPI 会把 `def` 路由丢进线程池执行，不会阻塞事件循环**；而 `async def` 路由里的同步阻塞调用（比如 `requests`）会卡死整个事件循环。这个点答好了非常加分

### P0-2 · 网络与 Web

**必答问题**

- HTTP 方法语义；哪些是幂等的（GET/PUT/DELETE 幂等，POST 不幂等）
- 状态码分类：1xx/2xx/3xx/4xx/5xx，各举一例
- **GET vs POST 的本质区别**（不是"参数在哪"，而是语义、幂等、缓存、长度）
- 常见状态码：200 / 301 / 302 / 304 / 400 / 401 / 403 / 404 / 422 / 500 / 502 / 504
- **401 vs 403 的区别**（未认证 vs 已认证但无权限）——你的 `get_current_user` 返回 401、`get_current_admin` 返回 403，正好是这个考点
- Cookie / Session / Token 三种状态保持方式的区别与优劣
- **JWT 三段结构**（header.payload.signature），payload 是**明文可解**的，所以不能放敏感信息
- **JWT 怎么注销？**（服务端无状态 → 黑名单 / 短过期 + refresh token / 版本号）
- **CORS 是什么，为什么会触发预检请求（OPTIONS），简单请求的条件**
- HTTPS 握手大致流程；对称加密 vs 非对称加密各自解决什么
- TCP 三次握手 / 四次挥手
- 输入 URL 到页面显示发生了什么
- SSE / WebSocket / 轮询 的对比与适用场景（你 L4 要用 SSE）

**用你项目的点来讲**

- **CORS 配置**（[main.py](../backend/app/main.py)）：`allow_origins` 明确写白名单而不是 `["*"]`，注释里还写了"不要直接写 `*`"；而 `allow_credentials=True` 与 `allow_origins=["*"]` **在浏览器上不能共存**——这是一个高频追问
- **JWT payload 只有 `user_id` 和 `exp`**（[jwt.py](../backend/app/utils/jwt.py)）：正好用来说明"为什么不把 `role` 放进 token"——放了之后管理员改角色，旧 token 里的角色还是旧的，权限就不一致了
- **CORS 预检**：前端带 `Authorization` 头，属于非简单请求，会先发 OPTIONS
- **文件上传**（[files.py](../backend/app/api/files.py)）：扩展名白名单 + 大小限制 + UUID 重命名 + `shutil.copyfileobj` 流式写入，可以讲"为什么要重命名"（防止路径穿越和同名覆盖）以及"为什么用流式而不是一次读进内存"（大文件 OOM）

### P0-3 · MySQL 与数据库

**必答问题**

- **索引原理：为什么用 B+ 树而不是 B 树 / 哈希 / 二叉树**（磁盘 IO 次数、范围查询、树高）
- 聚簇索引 vs 非聚簇索引；**回表**是什么；**覆盖索引**怎么避免回表
- **最左前缀原则**；`(a, b, c)` 联合索引，`where b = 1` 能走索引吗
- **索引失效的常见场景**（`like '%x'` 前置模糊、对字段做函数运算、隐式类型转换、`or` 连接非索引列）
- 事务四大特性 ACID；四种隔离级别；**脏读 / 不可重复读 / 幻读**分别对应哪个级别
- **MVCC 原理**（undo log + read view），为什么可重复读能避免不可重复读
- 乐观锁 vs 悲观锁的实现方式与适用场景
- 慢查询怎么排查（`explain` 关注哪些列、慢查询日志）
- 深分页为什么慢（`limit 1000000, 10`），怎么优化
- `count(*)` / `count(1)` / `count(字段)` 的区别
- 为什么业务数据用 MySQL、向量用 ChromaDB

**用你项目的点来讲**

- `users.username` 有 `unique=True`（[user.py](../backend/app/models/user.py)）→ 它既是唯一约束也是索引。用它讲"唯一约束在数据库层兜底，比应用层 `if exist` 更可靠"——这直接连到 L3 的双预约问题
- 分页查询（[user_service.py](../backend/app/services/user_service.py)）：先 `count()` 再 `offset/limit`，可以讲"两次查询之间数据变化会导致 total 与 list 不一致"以及"`ilike '%kw%'` 无法走索引"
- `create_all` 不是迁移（[main.py](../backend/app/main.py)）→ 讲"为什么生产必须用 Alembic"：加字段静默不生效、无法回滚、多人协作冲突
- 预约场景（L3 会做）：讲悲观锁 `SELECT ... FOR UPDATE` vs 唯一约束 vs 乐观锁版本号三种方案的取舍

### P1-4 · 框架与前端

**必答问题（后端）**

- FastAPI 的 `Depends` 依赖注入怎么工作，为什么能自动关闭资源
- Pydantic 校验时机：请求进来时校验 body、响应时校验返回值
- ORM 的 **N+1 问题**，懒加载 vs 急加载（`joinedload` / `selectinload`）
- ORM 与原生 SQL 各自适合什么场景
- 中间件执行顺序；异常处理器链路
- 同步路由 vs 异步路由的选择（见 P0-1）

**必答问题（前端）**

- **Vue3 响应式原理**：`Proxy` vs Vue2 的 `Object.defineProperty`，后者为什么监听不到数组下标和新增属性
- `ref` vs `reactive`；为什么 `ref` 要 `.value`
- `computed` vs `watch` 的区别与选择
- 虚拟 DOM 与 diff 算法（key 的作用）
- 组件通信方式（props/emit、provide/inject、事件总线、状态管理）
- 路由守卫的执行时机；`next()` / 返回值 两种写法
- 事件循环：宏任务与微任务，`Promise.then` / `setTimeout` 的执行顺序
- `v-model` 是语法糖，展开是什么
- 为什么要有 `axios` 拦截器，能解决什么问题

**用你项目的点来讲**

- **拦截器双套判断**（[request.js](../frontend/src/utils/request.js)）：成功回调里判断 `data.code !== 200`，错误回调里判断 `err.response.status`。这是"业务错误返回 200"设计的直接后果
- **路由守卫的漏洞**（[router/index.js](../frontend/src/router/index.js)）：只判断 token 存在，**不判断角色** → 学生可以直接打开 `/manager/user` 页面（虽然后端 `get_current_admin` 会拦下）。这是极好的"前端权限只是体验，后端才是安全边界"的例证
- **token 存哪**：现在存在客户端，可以讲 localStorage vs sessionStorage vs Cookie(HttpOnly) 的 XSS/CSRF 取舍
- **`onMounted` 加载数据**：讲"页面进入时机 vs 请求时序"，如果接口慢会先看到空表格 → 所以要 `v-loading`

## 四、算法刷题路线图

- LeetCode 简单题要能 15 分钟内一次过，中等题 30 分钟内讲清思路并写出来
- **每天 30 分钟，不许断** —— 这是肌肉记忆，不能等工程做完

| 阶段 | 类型 | 题量 | 关键套路 |

| 2 | 哈希表 | 10 | 空间换时间、去重、计数 |
| 3 | 字符串 | 10 | 反转、回文、子串 |

### 每道题的固定流程（**这个顺序就是面试的形式**）

1. **复述题目**，确认边界（空输入？重复元素？范围？）
2. **讲思路**和复杂度，先说暴力解再说优化
3. **写代码**，边写边解释变量含义
4. **手动跑一个样例**，检查边界
5. **说复杂度**，以及还能不能优化

### SQL 也要手写

`GROUP BY` + `HAVING`、多表连表、子查询、`LIMIT` 取第 N 高、窗口函数（`ROW_NUMBER` / `RANK`）。
练习方式：用你项目自己的表出题，比如"查每个实验室本周的预约数量，按数量倒序，只显示超过 3 条的"。

## 五、面试答稿模板与示例

### 通用模板（四段式）

> **结论 → 原理 → 项目实例 → 边界/取舍**

前三段决定你"会不会"，第四段决定你"是不是真做过"。

### 示例答稿 1：JWT 鉴权怎么做的？

**30 秒版**

> 登录成功后服务端用 HS256 签发 JWT，payload 只放 `user_id` 和过期时间，不放角色——因为 payload 是明文可解的，而且角色放进 token 后，管理员改权限旧 token 就不一致了。
> 前端把 token 存起来，axios 请求拦截器统一加上 `Authorization: Bearer`。后端用 `OAuth2PasswordBearer` 取出来解码，拿到 `user_id` 再查一次数据库确认用户还存在且未被禁用，然后注入到路由参数里。
> 权限分层用两个依赖：`get_current_user` 保证已登录，`get_current_admin` 在其之上校验角色，未登录返回 401、无权限返回 403。

**展开 / 追问准备**

- **注销怎么做？** 纯 JWT 无状态，服务端删不掉。方案有三种：① 短过期 + refresh token；② 服务端维护黑名单（存 Redis，带过期时间）；③ 用户表加 token 版本号，签发时带上，校验时比对。我项目现在没做注销，只靠 24 小时过期
- **和 Session 的区别？** Session 服务端存状态、靠 Cookie 带 sessionId，天然支持注销但多机要共享存储；JWT 无状态易水平扩展但难注销
- **被窃取了怎么办？** 只能缩短有效期；以及用 HttpOnly Cookie 防 XSS，代价是要处理 CSRF
- **有个 bug 我知道**：用户被删除后旧 token 还能通过解码，代码里 `.first()` 返回 `None` 后直接取 `.status` 会 500，正确应该返回 401。（**主动暴露并说清修法，是加分的**）

### 示例答稿 2：预约冲突（双预约）怎么解决？

**30 秒版**

> 问题是两个用户同时预约同一实验室的同一时段，如果用「先查有没有冲突、没有再插入」，两个请求都查到"没冲突"，就都插进去了。
> 三种方案：① **数据库唯一约束** —— 把「实验室 ID + 日期 + 时段」建联合唯一索引，让数据库兜底，插入失败就返回"该时段已被预约"。最可靠，但只适用于时段是固定枚举的情况；② **悲观锁** —— 事务里 `SELECT ... FOR UPDATE` 锁住该实验室的行，再判断再插入，强一致但并发度低；③ **乐观锁** —— 表加版本号，更新时 `where version = ?`，冲突就重试，适合读多写少。
> 我选的是方案 ①，因为实验室预约的时段是固定的节次，能做唯一约束，而且不依赖应用层代码正确性。我用脚本模拟了 10 个并发请求验证过。

**这个答法的价值**：完整覆盖了「问题本质 → 三个方案 → 选择依据 → 验证方式」，这是系统设计类问题的标准结构。

### 示例答稿 3：RAG 流程与失败模式

**30 秒版**

> RAG 分五步：文档解析 → 切分 → 向量化入库 → 检索 → 拼进 prompt 生成。
> 每一步都有典型失败：解析阶段 PDF 表格和公式容易丢；切分太小语义断裂、太大检索不到重点，所以我做了 chunk 大小对比实验；检索阶段 top_k 和相似度阈值拍脑袋会导致召回的上下文不相关；生成阶段如果不给来源约束，模型会把检索到的和编的混在一起。
> 我的兜底是：检索相似度低于阈值就直接回答"我没有这方面的资料"，并且回答里必须标注来源，让用户能自己核对。

**追问准备**

- 为什么不用 `LIKE` 做检索？→ 字面匹配无法处理同义词和自然语言问句
- embedding 是什么？→ 把文本映射成高维向量，语义相近的向量距离近；用余弦相似度是因为只关心方向不关心长度
- 向量库为什么快？→ ANN 近似最近邻，HNSW 是分层图跳跃，牺牲少量精度换数量级的速度
- 怎么评估效果？→ 我准备了 20 条测试集，每次改 prompt 或切分策略都跑一遍对比通过率

## 六、面试流程与时间分配

实习面试通常 40–60 分钟：

| 环节 | 时长 | 你要准备什么 |
| --- | --- | --- |
| 自我介绍 | 3–5 min | 90 秒版本，讲清项目是什么 + 你的角色 + 一个亮点 |
| 项目深挖 | 15–20 min | **权重最高**。架构图、链路、难点故事、失败反思 |
| 基础理论 | 10–15 min | 本文件 P0 全部 + P1 挑你项目相关的 |
| 算法 | 15–25 min | 1–2 题，边写边讲 |
| 反问环节 | 5 min | 准备 2–3 个真问题（团队技术栈？实习生做什么？） |

**笔试**（多数公司实习有）：2–3 道算法 + 选择题（计算机基础 / 概率 / 编程语言），算法权重 60%+。

**自我介绍 90 秒模板**

> 我是 XX，XX 学校 XX 专业。最近在做一个基于 AI Agent 的实验室预约系统，技术栈是 Vue3 + FastAPI + MySQL + ChromaDB，我在里面负责……（讲你真正主导的部分）。
> 目前完成了登录鉴权、用户管理和文件上传，正在做预约模块的并发控制。我比较在意的是……（一个技术判断，比如"把业务错误统一返回 200 的取舍"）。
> 想找一份后端 / AI 应用方向的实习。
