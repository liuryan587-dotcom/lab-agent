## 五、按本仓库的目标（找实习）怎么用这份 PDF

[面试知识树.md](面试知识树.md) 的核心原则是"以项目为索引、讲取舍、给代价"，这份 PDF 恰好是反面：
它给你 800 个"标准答案"，但不给任何"为什么这样选、代价是什么"。所以：

**① 当 Checklist，不当教材。**
先按篇扫题号，只做一件事：标记"我完全没听过"的题 → 这才是它的最大价值（覆盖面广、题号连续、便于逐条打勾）。
已听过的题**不要读它的答案**，避免被通用表述覆盖掉你项目里的真实细节。

**② 优先级排序（结合 lab-agent + 找实习场景）**

| 优先级 | 范围 | 理由 |
| --- | --- | --- |
| P0 | Agent 篇 RAG（271–276、301–305、357–358）、工具调用与 MCP（266–267、270、328）、记忆/上下文（265、278、327、361）、可观测与评估（292–293、399、414）、安全护栏（290、308、310） | 与 lab-agent 的 RAG/Agent 模块直接对口，面试官必问 |
| P0 | FastAPI 篇 163（生命周期）、171/176/199（依赖注入与缓存）、186/217/219（事务边界）、202/256（SSE 流式）、252（CORS）、258（request_id）、235（JWT） | 你的后端就在写这些，答案里的参数名可直接对照代码 |
| P1 | Python 篇 4/40（可变性）、62（闭包）、86–89（生成器迭代器）、98–113（并发/协程/GIL）、73（GC）、104（死锁） | 知识树里的 L1 理论闭环 |
| P2 | 大模型篇 431–434（Transformer）、435–436（微调/RLHF）、439–440（采样）、470–476（RAG/向量） | L4 理论，够用即可 |
| P3 | Redis 621–634（结构/淘汰/缓存三问题）、642/691（分布式锁）、647/648（哨兵/集群）；PG 725–729（MVCC/索引/JSONB）、795–796（索引与慢 SQL）；Nginx 567/568/570/581/601 | 按项目用到再补，别按篇刷 |

**③ 每条答案自己补 2–3 倍：把"是什么"改写为"结论 + 取舍 + 项目证据"。**
例：PDF 里 Q632"缓存穿透用布隆过滤器"，
改写为"我的 lab-agent 里知识库检索走 Redis 缓存，key 用 `kb:{id}:{query_hash}`；空结果我选择**缓存空值 60s** 而不是上布隆过滤器，因为租户维度多、布隆过滤器重建成本高于收益；代价是恶意随机 query 会打满一层假 key，所以加了 60s TTL + 单租户 QPS 限流。"

**④ 把它标出的错误当作"不要背错"清单。**
第四节第 5 条的表格建议直接对照检查；尤其 Python 3.13 no-GIL、Pydantic v2 参数、Redis 7 listpack、PG `serial`/`IDENTITY`、Nginx location 优先级这几处，是面试官很爱追问的点。
