# L1 冲刺计划：8 次学习，每次约 8 小时

> 目标：**L1 · 语言与工具地基** ——「给你任意一个 `.py` 或 `.vue` 文件，你能逐行口述它的执行顺序和数据流向」。
> 依据：[学习路线.md](学习路线.md) 的 L1 全部内容 + [面试知识树.md](面试知识树.md) 的「L1 双轨同步点」。
> 前提：按每天 8 小时设计。若某次 4 小时就做完了，就当天结束，不要为了凑时间灌水；若某次超时，用第 8 次还债。

---

## 开头先看这几条（别跳）

**1. L1 乱，是因为它是「散点」；能把它串起来的只有一条线——数据。**
L1 的 8 个主题（Python / 环境 / JS / HTTP / JSON / Git / 调试 / 运行）不是并列的章节，它们全都服务于同一个问题：
**「这次登录，数据从哪来、变成了什么形状、到哪去了？」**
所以本计划不按「Python → JS → HTTP」的教材顺序排，而是按 **一次真实请求的生命周期** 排。每完成一次，你就多拥有一段能讲出来的链路。

**2. 硬先决条件（Day 1 开始前必须有）**
- [ ] MySQL 已启动，`backend/.env` 里的 `DATABASE_URL` 能连上
- [ ] 后端能起来：`backend` 目录下 `uv run uvicorn app.main:app --reload`
- [ ] 前端能起来：`frontend` 目录下 `npm run dev`
- [ ] 浏览器能登录成功（账号密码你自己知道）
- [ ] 有编辑器可以打断点（VS Code / PyCharm 都行）

跑不起来就别开始 Day 1 的读代码部分，先花时间跑起来。**跑不起来的 L1 是空的。**

**3. 「最主要内容」优先级排序（时间被压缩时按这个顺序砍）**

| 优先级 | 内容 | 为什么 |
| --- | --- | --- |
| P0 | 环境能跑 + 会读报错栈定位文件 | 没有这个，后面全部卡死，也是 L1 唯一的「技能型」产出 |
| P0 | Network 面板看懂一次登录请求 | 前端 → 后端之间到底传了什么，只有这里能看到 |
| P1 | 逐行注释 `auth_service.py` + `Login.vue` | 晋级清单里的两项，且是 L2 的直接地基 |
| P1 | Git 拆 commit | 便宜、马上有用、不练就一直是「做完才提交」 |
| P2 | Python 异步 / GIL / 事件循环 | 面试高频，但可以放到 Day 7 集中处理 |
| P2 | HTTP 状态码 / CORS / JWT 结构 | 背了就会，不需要大块时间，碎片时间做 |
| P3 | 数据库 / SQL | 严格说是 L3 的内容，L1 只需要「看得懂查询在做什么」 |

**P0 + P1 大约 30 小时。也就是说：如果只能投 4 天，做完 Day 1–5 就够晋级，Day 6–8 是加固。**

**4. 每天固定动作（雷打不动）**
- 开始前 10 分钟：回忆昨天最后一次「报错定位」是怎么做的，写在纸上
- 结束前 20 分钟：**关掉所有资料**，对着空气讲 3 分钟「今天这条链路的完整数据流」，卡壳的地方写进错题本
- 全程：**30 分钟算法题（数组 / 哈希 / 字符串起步），不许断** —— 面试知识树里明确写了这条不能延后。它不占这 8 小时，但它是独立的一条命

**5. 硬禁令（违反一次，这级就白练）**
- ❌ 报错截图 / 报错原文直接丢给 AI 要代码。**必须自己读完整个栈，说出「哪个文件哪一行」**，才能去查
- ❌ 跟教程视频敲。L1 的作业全部基于本项目真实代码，没有视频
- ❌ 只看不写。每次作业都要有**可检查的产出物**（文件、commit、截图、表格、能讲出来的话）

## Day 1 · 环境、跑起来、读懂第一个报错

**学习目标（结束时必须能做到）**
1. 能说出本项目从「按下 npm run dev」到「登录成功」涉及几个进程、各占哪个端口
2. 能解释虚拟环境是什么，为什么不能全局 pip 装包
3. 能解释 `pyproject.toml` 和 `uv.lock` 各管什么，为什么依赖要锁版本
4. 能故意把配置改坏，然后**只靠报错栈**说出是哪个文件哪一行、哪个变量导致的

**8 小时怎么分**
- 0:00–0:30 热身：不查资料，先写下你以为的启动步骤，再实际操作一遍，标出所有和你以为的不一样的地方
- 0:30–2:30 环境三件套：`backend/pyproject.toml`、`backend/uv.lock`、`backend/.env`、`backend/.python-version`
- 2:30–4:00 跑起来：后端（`/docs` 能打开）、前端、登录一次
- 4:00–5:00 画图：把进程、端口、数据方向画出来
- 5:00–6:30 作业 1（故意的报错）
- 6:30–7:40 作业 2（依赖跑偏实验）
- 7:40–8:00 收尾：3 分钟口述「今天这条链路」

**练习任务**

**作业 1 · 故意把 `.env` 里的 `DATABASE_URL` 改错，从报错定位到文件（必做，L1 清单项）**
1. 先提交一次当前状态，保证有退路：`git add -A; git commit -m "chore: 学习前保存当前进度"`
2. 把 `DATABASE_URL` 的端口从 `3306` 改成 `3307`，重启后端，登录一次
3. 一字不改地抄下**完整报错栈**（不是第一行，是全部）
4. 在报错栈里标出三个东西：**最底层的原始错误**、**报错发生在项目里的哪一行**、**这个错误是被谁抛出的**
5. 改回去，确认恢复
6. 产出：一个 `notes/day1-报错栈.md`，写清楚「从哪一行往上看、看到什么关键词就知道是配置问题」

> 常见坑：只截前两行就以为看懂了。第三方库的栈要**从最后一行往上读**，第一行往往只是「服务启动失败」这种没信息量的话。

**作业 2 · 依赖跑偏实验（10 分钟，理解锁版本）**
1. 在 `backend` 里执行 `uv run python -c "import sqlalchemy, os; print(sqlalchemy.__file__)"`
2. 再在项目根目录（不在 venv 里）执行 `python -c "import sqlalchemy"`，看报错还是看另一个路径
3. 写下结论：**同一个包名，两个 Python 解释器，能找到两个不同的版本**。这就是为什么必须锁版本、必须用 venv

**作业 3 · 找错「娘家」的预热（只看，别改）**
读 `backend/app/services/auth_service.py` 第 8 行：
```python
from pymysql import IntegrityError
```
先不查资料，只用一条命令验证 **SQLAlchemy 到底抛的是哪个 IntegrityError**（提示：`python -c "import sqlalchemy.exc, pymysql; print(sqlalchemy.exc.IntegrityError, pymysql.err.IntegrityError)"`）。
把结论写进 notes。**这个 bug 是 L2 要修的，Day 1 只需要亲眼确认它存在。**

**验收标准（4 条全过才算过）**
- [ ] 能不看书说出：前端 `5173`、后端 `8000`、MySQL `3306`，以及 `vite.config.js` 里的 `/api` 代理是怎么把请求转过去的
- [ ] 能解释 `uv.lock` 和 `package-lock.json` 的存在意义（一句话：锁住整棵依赖树的确切版本，保证任何人装出一样的）
- [ ] 报错时第一反应是读栈，能指出「哪个文件哪一行」
- [ ] `notes/day1-报错栈.md` 写完，含完整栈和你的定位过程

**常见坑**
- 环境混用：全局 pip 装了 `fastapi`，venv 里也有一份，然后 import 到错的那个
- 把「服务起来了」当成「环境配好了」——不知道 `uvicorn` 是谁启动的、`--reload` 干了什么
- `.env` 提交进了 git（`.env` 应该只在 `.gitignore` 里，`config.py` 通过 `env_file` 读它）

## Day 2 · 逐行读懂 `auth_service.py`（Python 地基）

**学习目标**
1. 能逐行口述 `backend/app/services/auth_service.py` 的每一行「执行时手里有什么数据」
2. 掌握：函数与返回值、类与 `self`、`str | None` 类型注解、模块与导入、`try/except/finally`、闭包/生成器的最直观用法
3. 能说出 `login()` 里每一种失败分别走到哪一行、抛什么

**8 小时怎么分**
- 0:00–0:20 热身：合上文件，白纸手写 `login()` 的执行流程，再打开对照
- 0:20–2:20 逐行批注 `auth_service.py`（44 行，慢一点没关系）
- 2:20–3:20 读 `backend/app/database.py`（33 行），重点搞懂 `yield` 和 `SessionLocal`
- 3:20–4:20 读 `backend/app/utils/password.py` + `backend/app/schemas/auth.py`
- 4:20–6:00 作业 1、作业 2
- 6:00–7:20 作业 3（异常实验）
- 7:20–8:00 收尾口述 + 错题本

**练习任务**

**作业 1 · 逐行批注（必做，L1 清单项）**
复制一份到 `notes/auth_service_annotated.py`，**每一行后面写注释，格式固定**：
```
user = db.query(User).filter(User.username == data.username).first()
# 手里有：data.username = "zhangsan"（来自请求体，已过 Pydantic）
# 拿到后：user 是 User 对象 或 None
# 副作用：发了一条 SELECT，不改数据库
```
规则：
- 必须写「**输入是什么值**」和「**输出是对象还是 None**」，这两样写不出来就是没懂
- `if not user or not verify_password(...)` 这一行要拆成两种独立情况分别写
- 第 19 行 `user.status != 1`：要能说出 `1` 是什么（魔法数字），换成枚举会怎样

**作业 2 · `yield` 到底是什么（Python 生成器，面试必问）**
`database.py` 第 12–17 行：
```python
def get_db():
    db = SessionLocal()
    try:
        yield db
    finally:
        db.close()
```
1. 先把它当普通函数看：调用 `get_db()` 得到什么？（答案：一个生成器对象，不是 session）
2. 写一个 5 行的最小实验验证：`g = get_db(); print(g)`，再用 `next(g)` 看它停在 `yield` 处
3. 回答：**为什么请求结束 `db.close()` 一定会执行？**（提示：谁在 `finally` 里、请求出错时生成器怎么被关闭）
4. 把它翻译成一句话讲给面试官听：「FastAPI 的依赖注入靠生成器实现请求级资源的自动回收」

**作业 3 · 异常实验（动手，别只读）**
1. 用 Swagger（`http://127.0.0.1:8000/docs`）调 `/api/auth/login`，分别构造：
   - 用户名不存在
   - 密码错误
   - 用户 `status = 0`
   - 请求体缺 `password` 字段
   - 请求体 `password` 超过 72 字节
2. 每种记录：**HTTP 状态码** + **body 里的 `code`** + **message** + **代码走到哪一行**
3. 做完你会发现一个反直觉的现象：**前三种都是 HTTP 200**。在笔记里写下为什么（读 `backend/app/common/exceptions.py`），以及这个约定的代价是什么

**验收标准**
- [ ] 能不看文件说出 `login()` 的完整分支：查不到 → 密码错 → 被禁用 → 签发 token
- [ ] 能解释 `db.query(...).first()` 为什么可能返回 `None`，以及紧接着取 `.status` 会怎样（**对照 `backend/app/dependencies/auth.py` 第 30–31 行，那个 Bug 现在你应该能一眼看出来**）
- [ ] 能解释 `try/except/finally` 三者各自在什么时机执行
- [ ] 能解释 `str | None` 这种写法解决了什么问题（对比老写法 `Optional[str]`）
- [ ] 批注文件写完，且每一行都有「输入值 / 输出形状」

**常见坑**
- 把「跑通了」当「会了」：不看代码就以为登录是「密码直接比对字符串」
- 分不清「函数定义」和「函数调用」：`Depends(get_db)` 传的是函数本身，不是 `get_db()`
- `except IntegrityError` 抓不到（Day 1 已经验证过），这里要再确认一次 `auth_service.py` 第 8 行用的是哪个包

   把预测 vs 实际写成对照表。**这张表就是 Day 7 事件循环的伏笔。**
   产出：`notes/day3-js实验.md`

**作业 2 · 逐行批注 `Login.vue`（必做，L1 清单项）**
同样复制到 `notes/login_annotated.vue`，逐行注释。必须写清楚这几处：
- `const form = reactive({ username: '', password: '' })` —— 为什么用 `reactive` 而不是 `ref`？改动 `form.username` 后，页面上哪个位置会重新渲染？
- `const formRef = ref(null)` —— `ref` 拿到的是 DOM 还是组件实例？`.value.validate()` 调的是谁的方法？
- `v-model="form.username"` —— **语法糖展开成什么**？（提示：`:model-value` + `@update:model-value`）
- `:loading="loadingValue"` —— `loadingValue` 从 `false` 到 `true` 再到 `false`，页面上发生了什么？
- `await loginApi(form)` —— `form` 是个响应式对象，**传给 axios 的时候它还是响应式对象吗？被序列化成什么了？**
- `catch (error) {}` 里为什么是空的？错误提示到底是谁显示的？（答案在 `request.js`，这就是链路）

**作业 3 · 拦截器实验（这是 L1 里最值钱的 10 分钟）**
1. 打开浏览器 DevTools → Network，勾选 Fetch/XHR，登录一次
2. 点开 `/api/auth/login` 这条请求，照抄出五件套：**URL / 方法 / 请求头（特别是 `Authorization`）/ 请求体 / 响应体 / 状态码**
3. 现在看拦截器：这次登录请求的 `Authorization` 头**有还是没有**？为什么？（提示：token 是这次请求的**响应**才拿到的）
4. 登录成功后，点任意一个需要鉴权的页面（如用户管理），再看那条请求的 `Authorization` 头
5. 故意把 `localStorage` 里的 token 改掉一个字符，刷新页面，观察：**走的是 `res` 成功回调还是 `err` 错误回调？** `data.code` 是多少？HTTP 状态码是多少？
6. 把 3、5 两步的截图/记录写进 `notes/day3-拦截器实验.md`，并回答：**为什么 `request.js` 里要写两套 401 判断**（第 30 行 `data.code === 401` 和第 41 行 `httpStatusCode === 401`）

## Day 4 · HTTP 本质 + Network 面板实战

**学习目标**
1. 能说清 HTTP 请求/响应的完整结构，方法语义与幂等性
2. 状态码能张口就来：200 / 301 / 302 / 304 / 400 / 401 / 403 / 404 / 422 / 500
3. **401 vs 403** 能讲清区别，并能对应到本项目代码
4. 能拆开 JWT 三段，说出 payload 为什么不能放敏感信息、为什么不放 `role`
5. 能解释 CORS 预检请求为什么会发生

**8 小时怎么分**
- 0:00–1:30 HTTP 基础（方法 / 状态码 / Header / body / Query）
- 1:30–3:00 作业 1（Swagger 错误请求矩阵）
- 3:00–4:30 作业 2（真实请求五件套 + 拆 JWT）

2. 前端：一个输入框 + 按钮，点下去请求后端，把 `message` 显示在页面上
3. 允许：查官方文档、看你自己的笔记
4. 不允许：看本项目代码、看视频
5. 计时。**超过 30 分钟就要记录卡在哪一步，这就是你真实的短板**（大概率是环境/CORS/端口，而不是语法）
6. 加分项（做完基础版再考虑）：加一个 `try/except`，让前端能显示后端的错误提示

**作业 2 · 给 demo 加一次故意报错**
1. 把 demo 后端的端口改掉，但不改前端 → 观察前端报什么错
2. 把请求体的字段名拼错 → 观察后端返回什么（**应该是 422**）
3. 每次都要走完流程：**读栈/看 Network → 说出哪个文件哪一行 → 再改**
4. 这一步是 L1 的最终形态：**报错时第一反应是读栈和查 Network，而不是搜索。**

**作业 5 · 录 10 分钟讲一遍（最重要的一步）**

2. 每一跳的数据形状
3. 你踩过的 3 个坑和怎么定位的
